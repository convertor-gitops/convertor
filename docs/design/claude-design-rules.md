# Convertor 编排工作台 · 第 1 轮

请为 Convertor 设计编排工作台的主屏，这一轮聚焦**分流规则**的编辑。下面先介绍这个项目，再说明这一屏的内容和数据。

## 这是什么

Convertor 是给代理订阅重度用户的配置编排工具。

用户手里有一两个机场订阅。每个订阅是一份完整的 Surge 或 Clash 配置：几十上百个节点、机场预设的策略组、一长串分流规则。机场的组织方式很少恰好合用：用户想把几个家宽节点单独拎出来给 AI 服务用，想按"地区 → 来源"重新分组，想沿用机场的分流规则、但把目标换成自己的组。

在 Convertor 里，用户把这些意图写成一份**方案**。方案里存的是规则，订阅内容变了，规则依然成立：

- 名称包含"家宽"的节点，打上「家宽」标签
- 「家宽」组 = 具有家宽标签的节点，自动测速
- chat.example.test 走「家宽」
- 取 BosLife 的域名和 GEOIP 规则：原目标是 DIRECT 的保持直连，值里带 video 的走「家宽」，其余走「总入口」

方案最后生成一条订阅链接，交给 Surge / Clash。客户端每次更新时，服务端用订阅的最新内容重新执行方案：机场增删节点后，组和规则自动跟上。

所以这个产品的核心是一个**编辑器**。用户在写一份小型的声明式程序（条件、引用、顺序），需要随时看到它在当前订阅内容上算出的结果，并能从任意一条结果追溯到产生它的条件。用户熟悉节点、策略组、分流规则，会花很长时间在里面精调，看重密度、精确和可追溯。

## 编排的结构

一份方案沿数据流依次经过这些环节，左侧方案大纲也按这个顺序排列：

1. **来源**：订阅链接或粘贴的配置文本。每个来源带着自己的节点、原始组和原始规则，可以设一个过滤条件，保留满足条件的节点。
2. **标签**：在某个来源里，给满足条件的节点打标签。同一个标签可以由多个来源各自的条件产生。
3. **自动分组**：按有序维度（地区、来源、协议、是否具有某标签）逐层生成组树。"地区 → 来源"和"来源 → 地区"是两棵不同的树。
4. **自定义组**：有名字的组，行为是手动选择或自动测速。成员来自一串有序的成员来源：按条件选节点、展开原始组、保留原始组为子组、引用自动组、引用其他自定义组、DIRECT / REJECT。
5. **分流规则**：一个有序的规则块列表。
6. **输出**：兜底目标、基础设置来源。

界面里同时存在三样东西，用户需要一眼分清：**方案**（用户写下的条件和顺序）、**快照**（订阅此刻的内容）、**结果**（方案作用在快照上的产出）。

## 本轮重点：分流规则

分流规则是一个有序列表，混排两种块。

**手工规则块**：用户直接写规则。每行是 类型 + 值 + 目标，可加选项（如 no-resolve）和备注。类型有 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、PROCESS-NAME、USER-AGENT、GEOIP、IP-CIDR、IP-CIDR6、RULE-SET。

**来源规则块**：从某个来源的原始规则里按条件挑出一部分，保持它们在来源里的原有顺序，再决定目标。目标有三种处理方式：

- **统一替换**：挑中的规则全部指向一个目标。
- **保留来源目标**：沿用规则原本的目标。
- **按条件映射**：一组有序分支，每条分支是"条件 → 目标"，**每条规则采用第一条命中的分支**。所有分支都没命中时，用户从四种处理里选一种：报错并阻断 / 丢弃该规则 / 保留来源目标 / 使用固定目标。

可选的目标是方案里的自定义组、DIRECT、REJECT。整份配置末尾有唯一一条兜底规则（Surge 写作 FINAL），目标在输出设置里选，在结果里显示为最后一行。来源里的 FINAL 是该来源自己的兜底，展开时统一由方案的兜底代替。

最终规则严格按块的顺序展开，块内保持各自的顺序，用户完全掌握每条规则的位置。两个块挑中同一条来源规则时，它会出现两次，结果如实呈现。

### 条件编辑器

条件编辑器在整个产品里反复出现（打标签、过滤、选成员、挑规则、映射分支），结构统一：

- 条件组：全部满足 / 任一满足 / 不满足，可以嵌套。
- 单个条件：字段 + 运算 + 值。
- 规则场景的字段：类型、值、原始目标名。
- 运算：等于、属于列表、包含任一、开头是、结尾是、正则（可选忽略大小写）。"属于列表"和"包含任一"的值是多个 chip。

每个条件旁边显示它当前命中了几条，可以展开看是哪几条。空的"全部满足"命中全部，空的"任一满足"一条也不命中，界面直接写出这个含义。

## 这一屏

工作台主屏，选中"分流规则"。桌面 1440×900，深色。

**左栏 · 方案大纲**
来源 2 · 标签 1 · 自动分组 1 · 自定义组 2 · 分流规则 3 · 输出。每项显示数量和问题标记，"分流规则"为选中状态。下方（或页签）是资源浏览：节点 / 原始组 / 原始规则。本轮展示"原始规则"，按来源分组，被当前选中块挑中的规则带标记。

**中间 · 分流规则编辑器**
三个块，可展开、折叠、调整顺序（按钮和拖拽都可以）：

1. 手工规则块（3 条）
2. BosLife 来源规则块，**展开编辑状态**：挑选条件、目标处理"按条件映射"、两条分支、未命中处理
3. 备用订阅来源规则块，折叠状态

**右栏 · 结果检查器**
展开后的最终规则，每行标明来自哪个块、映射时采用了哪条分支，最后一行是兜底。选中中间的某条分支时，右侧高亮由它决定目标的规则；满足条件、但被前面分支先采用的规则用另一种更弱的标记。选中右侧某条规则时，中间定位到产生它的块和分支。下方是问题列表。

**顶部状态条**
客户端 Surge、草稿已保存到此浏览器、预览有效、"生成订阅链接"按钮。

这一屏要能真实操作：增删条件行和分支、调整块和分支的顺序、切换目标处理方式和未命中处理、修改条件的值。结果检查器根据下面的数据实时展开，逻辑很直接：按块顺序展开，块内保持来源顺序，映射取第一条命中的分支，未命中按所选方式处理，FINAL 只在最后出现一次。

两个值得做得顺手的瞬间：

- 对调 BosLife 块的两条分支后，video-cdn.example.test 的目标从 DIRECT 变成「家宽」：它同时满足两条分支，排在前面的那条生效。
- 把未命中处理改成"报错并阻断"后，api.example.test 没有命中任何分支，问题列表出现一条阻断问题，点击后定位到这个块的未命中设置。

## 视觉

专业的桌面工具。空间留给条件、规则和结果，信息紧凑、层级清晰，适合长时间盯着看。深色为主，浅色随后做。中文界面；规则类型、域名、IP 等配置值用等宽字体。状态同时用图标、文字和颜色表达。"当前选中"和"条件命中"是两种不同的高亮，会同时出现在同一个列表里。

可以参考 Linear 的密度和质感，VS Code 里大纲、编辑器与问题面板之间的关系，以及 Linear / Notion 筛选器的条件编辑方式。
