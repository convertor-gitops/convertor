# 修改意见 · 第 1 轮

这一版的数据、计算逻辑和很多细节都很好。接下来把界面整理成三个模块，并让编排成为主角。

## 保留

- 顶栏：客户端、预览状态、节点与组统计、空方案 / 完整方案 / 快照 A / B、生成订阅链接
- 输入节点的细节：原始标签与方案标签的区分、已过滤标记和原因、"N 个组"
- 输出预览的组树和配置文本切换
- 现有的演示数据和计算逻辑

## 三个模块

界面由三个模块组成。从左到右是数据流的方向，三者同时可见、随时可操作：

| 模块 | 是什么 | 放什么 |
| --- | --- | --- |
| **源**（输入） | 来源此刻的内容 | 来源列表（添加、链接遮挡显示、加载状态、刷新）；输入节点（搜索、按来源 / 地区 / 协议 / 标签查看、多选）；原始组和原始规则 |
| **编排** | 用户写下的方案 | 标签、过滤、自动组、自定义组；分流规则和输出设置留入口 |
| **渲染**（输出） | 方案作用在源上的结果 | 输出预览（组树）、配置文本、订阅链接 |

每个模块有清楚的标题和自己的视觉身份，一眼就能看出自己在源、编排还是渲染里。概念说明收进一个帮助入口。

## 编排是主角

- 编排模块最宽。打开时默认选中自定义组「家宽」，编辑器里有内容。
- 编排里的对象：
  - **标签**：标签名，每个来源一块条件，旁边显示命中数。
  - **过滤**：每个来源一条保留条件，显示去掉了哪些节点。
  - **自动组**：维度列表（拖拽排序、增删）和组行为；下面是它生成的组树和每组节点数，调整维度时当场重排。
  - **自定义组**：名称、组行为、是否顶层输出；有序的成员来源，每条显示带进来的成员数；再下面是当前成员。
- 在编排里切换对象要快；编辑器要舒展，条件编辑器的嵌套、chip 和候选下拉都放得开。
- 源和渲染可以收窄或折叠，把空间让给编排。1440px 下节点名和组名完整显示。

## 模块之间的联动

- **编排 → 源**：编辑一个条件时，源里命中的输入节点高亮。
- **源 → 编排**：在源里多选节点，可以打标签、新建自定义组，或加入当前正在编辑的自定义组（名字并入名单）。
- **编排 → 渲染**：每次修改，渲染马上更新，受影响的组和节点高亮。
- **渲染 → 编排 / 源**：点输出里的组或节点，编排切到产生它的对象，源里定位到对应的输入节点。
- **刷新源**：渲染随之变化并标出差异，编排保持不变。

## 视觉

在新布局上给出三个差异明显的视觉方向，配色、字号、密度和表面层次各不相同，用调节项切换，方便我对比。

## 做法

先搭三个模块的框架，再逐个改编排里的对象（标签、过滤、自动组、自定义组），然后做模块之间的联动，最后做视觉方向。每次只改一块，改完打开检查。
