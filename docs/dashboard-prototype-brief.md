# Convertor Dashboard 改造：Claude Design 原型需求

状态：原型设计委托稿。日期：2026-09-15。

本文可直接交给 Claude Design，作为独立、自包含的产品需求。补充技术资料是同目录的 [Plan 配置编排协议设计](plan.md)。技术文档中的待定编码和实现细节，不应阻塞原型设计，也不要在界面中展示 Rust 类型或协议字段。

## 1. 给 Claude Design 的任务

请为我现有的 **Convertor Dashboard** 设计一个可交互、高保真的改造原型。

Convertor 是代理订阅转换工具。当前 Dashboard 主要用于输入一个订阅地址、生成转换链接，以及预览并注入本地 Surge 配置。现在我要将它升级成 **多源代理配置编排工作台**。

用户应该可以看到各个来源提供的节点、原始策略组和规则，补充分类标签，定义自己的组及成员选择条件，安排规则优先级，最后生成一条可交给 Surge 的 GET 订阅 URL。

请围绕真实编辑任务设计，提供能够操作和验证的原型。主工作区直接展示一个有内容的示例方案，同时提供清空后新建方案的入口。

交付请包括：

1. 可交互的桌面端主原型及主要窄屏状态。
2. 来源、标注、组、规则、预览和导出的完整主流程。
3. 至少一组来源更新前后的模拟数据，用于演示动态编排。
4. 关键异常、空状态和恢复操作。
5. 简短的设计说明：信息架构、关键交互、现有能力如何迁移。

不要求连接真实订阅、账号或后端，不需要实现正式编排协议或可供真实 Surge 使用的编码器。可以使用内存数据模拟，但模拟数据变化应真正驱动界面结果，不能只靠静态截图表示交互成功。

## 2. 产品目标和硬边界

### 2.1 核心目标

> 让用户通过当前配置快照进行所见即所得的编排，同时保存一套在未来订阅更新时仍会重新执行的规则。

主要使用者熟悉代理节点、策略组、规则和订阅，但不应该被要求编写 DSL 或直接修改配置文本才能完成核心流程。

### 2.2 必须遵守的边界

- 不做登录、注册、团队、成员、权限、计费或用户中心。
- 后端无状态，不替用户保存方案；完整编排方案随最终 GET URL 传递。
- 第一版没有 WebDAV、Git、网盘等外部方案存储依赖，也没有自动跨设备同步。
- 前端可以在当前浏览器自动保存草稿；跨设备通过导入导出链接或方案文件恢复。
- 当前版本的最终输出以 Surge 为主。现有产品具有 Clash 入口，但本轮不承诺完整的 Clash 编排；不要画出看似可用但没有定义的能力。
- 修改方案后必须重新生成链接，并在 Surge 更新链接；已有链接不会远程自动改写。
- 只更新来源内容而不改变编排定义时，原链接仍可使用，由后端按原规则重新生成。
- 压缩编码不能被称为加密；方案链接可能携带订阅凭据。导出区域应有简洁、就近的分享提示。
- 不把“发布到云端”“部署成功”“已同步所有设备”作为最终动作或状态。

“前端更重”指承担资源浏览、交互编辑、规则预览和方案管理，并不意味着必须引入拖拽连线画布。

## 3. 现有 Dashboard 与改造方向

当前页面的功能结构，依据项目现有模板与样式代码整理，未在本次委托中做运行截图核验：

| 当前区域 | 当前能力 | 改造后的安排建议 |
| --- | --- | --- |
| 顶栏 | Convertor 标识、后端状态、版本 | 保留品牌和服务状态，增加当前方案、本地保存及导出状态 |
| 订阅参数 | 单个订阅 URL、访问密钥、客户端、更新间隔、严格模式 | 来源编辑与输出设置分开，避免所有参数挤在首页表单 |
| 生成链接 | 原始、转换前后、Provider 等链接 | 主要动作聚焦最终 Surge 订阅链接，其余放次级区域 |
| 本地配置 | 授权目录、标记主配置和规则文件 | 作为交付后的可选辅助能力，不挡住导出主流程 |
| 注入预览 | 本地配置合并预览 | 保留可发现入口，原型可以用示例文件演示 |

已有客户端“更新间隔”和新组内的“测速间隔”不能混为同一个字段。访问密钥、服务地址等可以放在输出/连接设置中，不需要成为工作区视觉中心。

保留现有深色工作台气质。允许重新设计导航、布局和编辑方式，不要求继续沿用原来的三块固定卡片。

## 4. 用户应理解的对象

| 对象 | 用户语言 | 设计要求 |
| --- | --- | --- |
| 方案 | 一套完整的配置编排 | 当前浏览器可保存，导出后可恢复编辑 |
| 来源 | 一个订阅或导入配置 | 有独立名称、读取状态、节点、原始组和规则 |
| 当前快照 | 最近一次读取到的来源内容 | 显示更新时间；刷新可能改变匹配结果 |
| 标注 | 给某来源里的节点补充标签 | 标签来自原始来源或自定义标注，应能辨别来源 |
| 策略组 | 用户最终希望出现在 Surge 中的组 | 自己拥有成员选择条件，可以包含节点与其它组 |
| 基础组树 | 分组策略逐层分桶生成的组树 | 预览树和成员，编辑所属策略 |
| 规则 | 匹配什么流量，并让它走哪里 | 清晰表达顺序、来源和目标 |

不用独立的“表达式管理中心”或“全局节点容器”承载操作。编辑组时，就在该组内编辑成员来源和选择条件；编辑来源时，就在该来源内维护标注。

可以有跨来源节点总览作为浏览方式，但不要将它表现成必须维护、分配或搬运节点的全局池。

## 5. 信息架构与布局建议

建议的一级工作区：

- **来源**：添加输入、浏览原始资源、补充标签。
- **策略组**：管理输出组，编辑成员与动态生成方式。
- **规则**：维护自定义规则和来源规则块。
- **预览与导出**：检查配置、处理问题、生成订阅链接。

这些是功能范围，不要求机械地画成四个独立页面。可以使用左侧导航、实体列表、中部编辑、右侧实时结果的布局，也可以提出更清晰的结构。

设计要让用户持续知道：

1. 我正在编辑哪个对象？
2. 修改的是选择条件，还是正在查看匹配结果？
3. 当前会产生哪些节点、组和规则？
4. 是否存在阻止导出的问题？
5. 当前改动是否已包含在上次导出的链接里？

不要把所有对象和全部参数放在一个无限滚动表单。高频操作直接可见，低频高级选项渐进展开。不要用大量空白和大尺寸统计卡挤压实际编辑区域。

## 6. 来源工作区

### 6.1 添加与读取

- 支持添加多个订阅 URL，为来源命名。
- 支持粘贴配置或导入配置文件；原型可使用预置内容。
- 展示解析中、已读取、失败、需要刷新等状态。
- 切换来源后，能浏览该来源的“节点 / 原始组 / 原始规则”。
- 显示读取时间、节点数量、标注数量、来源过滤前后数量。
- 原始内容可放在辅助面板，不作为默认编辑界面。
- 刷新失败时可以保留上次快照供查看，但必须标识其过期状态，不把失败伪装成刷新成功。

### 6.2 节点浏览

节点列表至少包含名称、来源、协议、标签，以及必要的属性详情入口。

- 支持搜索、筛选、多选。
- 来源内同名节点不能在 UI 中不加区分地合并；详情可展示服务器和端口。
- 节点数量较多时应保持可用，可以设计分页或虚拟列表。
- 用户可以查看节点被哪些输出组使用，以及为何被选中。
- 连接凭据默认不在表格完整显示。

### 6.3 关键场景：BosLife 家宽标注

背景：BosLife 的美国节点曾经在名称里体现家宽，现在美国 07、08、09、10 的家宽信息只存在于官网标签，订阅名称无法区分。加拿大节点仍有“家宽”字样。

需要用户能够：

1. 在 BosLife 节点列表中选中美国 07～10。
2. 批量添加“家宽”标签。
3. 看到这实际上保存为来源内的标注规则：“名称精确属于这四个值 → 家宽”。
4. 再添加一条动态标注：“名称包含家宽 → 家宽”。
5. 在策略组中直接按标签选取，不必复制节点编号名单。

前端可以展示中文标签名“家宽”；技术示例中的标签键为 `residential`，映射属于原型展示约定。

需要区分：

- **原始标签**：来源本来提供。
- **自定义标签**：用户维护的标注结果。

标签规则可以修改和删除。删除自定义标注后重新计算结果；如果同一标签还有其它来源依据，不应一并消失。

不设计“AI 自动识别家宽”或“自动同步官网标签”按钮。这些能力没有输入依据，也不在第一版范围。

### 6.4 来源级过滤（原型按草案演示）

允许在来源内设置例如“排除名称包含到期的节点”。

界面应说明这是对该来源整体生效，所有组和导入路径都会受影响。显示筛选前后数量，并允许查看被排除的节点。

这类操作不是删除上游节点，也不是修改机场订阅。

## 7. 策略组工作区

### 7.1 组列表与编辑

至少支持创建、重命名、复制、删除组，设置手动选择或自动测速策略。

删除被规则或其它组引用的组时，列出受影响的引用，并要求处理引用或取消删除。不能留下无提示的失效目标。

组编辑包括：

- 名称和策略类型。
- 测速策略的 URL、间隔、容差等参数，按类型显示。
- 有序成员来源。
- 当前匹配节点、子组及总成员数。
- 空组时的行为与当前诊断。

### 7.2 成员添加方式

提供清晰的成员类型选择：

1. **从来源选节点**：选来源，填写条件。
2. **指定几个节点**：在来源节点列表中勾选，生成精确名称条件。
3. **取原始组中的节点**：选来源组，决定是否递归展开子组。
4. **保留原始组作为子组**：导入它的结构，不拍平成节点。
5. **引用本方案其它组**。
6. **引用动态生成的组**。
7. **添加 DIRECT / REJECT**。

“展开原始组的节点”和“保留原始组作为子组”必须有不同入口说明或明确选项，不能用一个含糊的“导入”操作掩盖差异。

一个节点可以同时被多个组使用，不做从一个容器拖走后另一个容器失去节点的搬运交互。

### 7.3 条件编辑器

需要结构化条件行，不以代码编辑器作为主入口：

- 字段：名称、协议、服务器、端口、标签。
- 运算：等于、属于列表、包含、前缀、后缀、正则；按字段限定可用操作。
- 组合：全部满足 / 任一满足 / 排除，允许嵌套条件组。
- 高级正则可折叠，同时展示错误与当前命中数。

例如：

```text
来源：BosLife
全部满足：
  标签包含：家宽
  协议等于：trojan
  排除：名称包含“到期”

当前匹配：5 个节点
```

支持预览具体匹配项和条件摘要。用户切换条件时，应立即看到计数和成员列表变化。

“指定几个节点”明确提示按名称匹配：地址更新可继续匹配，改名或消失则失配，同名节点可能全部匹配。提示应紧邻选择摘要，不需要反复弹窗。

勾选顺序不应暗示最终节点顺序；原型默认保持来源顺序。组内成员来源块可以重新排列。

### 7.4 分组策略与基础组树

分组策略针对所有来源经过标注、过滤后的节点。用户选择有序维度：地区、来源、协议或标签是否存在。

- `group_by` 从外到内逐层分组，拖动维度顺序会改变树形结构。
- `[Region, Source]` 表示地区组下包含来源子组；`[Source, Region]` 表示来源组下包含地区子组。
- 中间组只引用直接子组，最后一层持有节点；预览不能把整棵树扁平化展示成一个节点集合。
- 地区是内置分桶方式，识别、顺序与名称沿用当前项目；未知地区放入“未识别地区”。
- 每层名称由祖先到当前层的名称片段用连字符拼接；不提供单独命名模板。
- 节点增删会自动新增或删除桶和空路径；自动项只能跳回所属策略编辑，不能编辑一次性的派生结果。
- 多个策略分别生成基础组树，同一节点可参与多个策略。
- 自定义组通过基础组选择器选择“顶层组”或“全部层级”，再用深度、维度属性、名称筛选；选中组保留子树。
- `all` 是普通自定义组，选择策略的顶层组即可。
- 家宽采用来源标注加自定义组的标签选择，不作为地区分组的隐式附属组。

预览使用实际 Profile 与 Evaluator 结果；不引入独立快照文档模型。用户直接编辑的自定义组与派生基础组应在界面上清晰区分。Rust v1 字段和示例以 `docs/plan.md` 为准；不再使用 GroupFamily / GroupGenerator 或平级组合分桶的概念。

## 8. 规则工作区

规则核心是“顺序 + 来源 + 匹配内容 + 目标”。

### 8.1 两类规则块

- **自定义规则块**：用户手动维护域名、网段等规则。
- **来源规则块**：动态选取一个来源的规则，重映射目标。

提供顺序编号、拖动排序，以及可通过按钮/键盘执行的上移下移。来源块可折叠，展开时保留其内部原始顺序。

示例：

```text
01 自定义：internal.example → DIRECT
02 自定义：ai.example → 家宽自动
03 BosLife 来源规则：DIRECT/REJECT 保留，其它目标 → 日常访问
最后兜底：日常访问
```

### 8.2 必需操作

- 新增、编辑、删除自定义规则。
- 插入到指定位置，调整规则块和块内手工规则顺序。
- 选择来源规则，按类型、内容或原目标筛选。
- 将来源目标整体替换、逐项映射，或保留原目标结构。
- 展示原目标与新目标，目标选择器只列合法目标。
- 未映射规则必须有明确处理状态，不能静默猜测目标。
- 兜底固定显示为最后一项，不能随意拖到前面；来源兜底不会重复混入正文。
- 提供最终规则展开预览，让用户看到真实生效顺序。

不要加入未经实现的“已验证无冲突”或“自动优化分流”等承诺。基本诊断应覆盖悬空目标、解析失败、未支持规则和导出阻断。

## 9. 预览与导出

### 9.1 预览

提供两种互补视图：

- **结构预览**：输出节点、组树、成员来源、最终规则。
- **配置文本**：生成的 Surge 配置，支持复制或下载示例内容。

编辑时保持预览可访问，可以使用右侧面板、抽屉或切换标签。不要求时时占据一半屏幕。

问题应能定位回对象，例如“家宽自动当前无可用成员”，点击后进入对应组和条件。不要只给一个全屏错误提示而丢失编辑上下文。

### 9.2 需要区分的状态

| 状态 | 含义 |
| --- | --- |
| 本地已保存 | 草稿已保存于当前浏览器 |
| 来源已更新 | 本次来源 Profile 发生变化，重新计算预览 |
| 当前方案未导出 | 编排定义与上次生成链接不同 |
| 当前方案已导出 | 有一个对应当前定义的链接 |
| 预览有问题 | 当前 本次来源 Profile 下有阻断问题，需修复后生成新的产物 |

不要把“本地已保存”等同于“Surge 已使用新方案”。单纯刷新来源也不应自动标成“方案定义已修改”；即使原链接未变，新的来源内容仍可能引发空组等运行问题。

### 9.3 导出主动作

主按钮文案建议：“生成 Surge 订阅链接”。

导出区域至少有：

- 最终链接与复制按钮。
- 长度信息及必要的超限提示；实际阈值未知，原型超限为模拟场景。
- “修改方案后需在 Surge 替换链接”的简短说明。
- “链接可能包含订阅凭据，请勿公开分享”的简短提示。
- 下载方案文件、导入方案文件或链接继续编辑。
- 可选的配置下载及本地配置注入入口。

原型若未实现正式编码，链接明确标记为演示链接，不得提示已在真实 Surge 验证成功。文件可以用本地示例 JSON 完成往返恢复；其格式只是原型格式，不冒充正式协议。

主产品流里不放 Rust 类型、操作码、压缩算法等实现细节。只有原型能力标记需要简洁说明“演示”。

## 10. 演示数据与交互脚本

### 10.1 默认快照 A

BosLife 来源共 12 个原始节点：

| 节点 | 数量 | 说明 |
| --- | --- | --- |
| 🇺🇸 美国 07、08、09、10 | 4 | 使用完整名称；自定义标注为家宽，协议 trojan |
| 🇨🇦 加拿大 - 家宽 | 1 | 通过名称关键词标注为家宽，协议 trojan |
| 香港 01、香港 02、香港 03 | 3 | 普通节点 |
| 日本 01、日本 02 | 2 | 普通节点 |
| 新加坡 01 | 1 | 普通节点 |
| 到期提示 | 1 | 模拟来源内信息节点，被来源过滤排除 |

备用来源共 6 个节点：香港 B01、香港 B02、日本 B01、日本 B02、新加坡 B01、新加坡 B02。

备用来源含原始组“香港”，包含两个香港节点；再提供一个包含子组的“地区集合”，便于演示展开与保留结构的区别。全部节点的连接属性使用示例域名与虚构凭据。

页面可以展示：

- 原始节点总数 18，来源过滤后可用 17。
- 家宽自动：5 个节点。
- 香港手动：BosLife 的 3 个香港节点 + 备用的 2 个香港节点，共 5 个。
- 备用地区动态组：香港、日本、新加坡三组，每组 2 个节点。
- 日常访问：家宽自动、香港手动、三个备用地区组、DIRECT。
- 如果仅输出以上组，最终不同节点数为 14：不要将所有来源可用节点 17 误标成最终输出节点数。

规则模拟 8～12 条即可，至少含 DIRECT、REJECT、原代理策略，以及 2 条用户自定义规则。避免用成百上千条不可操作占位数据掩盖交互。

### 10.2 切换到快照 B

在原型演示控件中提供“模拟来源更新”，不要将开发用切换器伪装成正式业务功能。

模拟变化：

- BosLife 新增“香港 04”：香港手动增加一个成员。
- 美国 07 从本次来源消失：家宽自动减少一个成员，出现精确标注部分失配提示。
- BosLife 新增“🇺🇸 美国 11”：没有家宽标注，因此不会自动加入家宽组。
- 备用来源新增“德国 B01”：地区生成预设应支持德国，自动出现德国组，日常访问增加子组。

展示新增/移除差异。编排条件保持不变，不需要用户重新勾选节点。

另提供“所有家宽节点失配”异常状态，展示空组阻断及回到来源标注修复的路径。

### 10.3 必须可走通的完整脚本

1. 从示例方案进入来源页，查看 BosLife 节点。
2. 检查或修改美国节点的家宽标注。
3. 进入家宽自动组，确认其条件是“标签为家宽”，而不是固定名单。
4. 修改一个选择条件，预览实时改变，撤销或恢复后回到原结果。
5. 在规则页新增域名规则，指向家宽自动，并移到来源规则之前。
6. 查看结构与配置预览，完成演示导出。
7. 修改方案，看到“需要重新导出”，本地保存状态仍然正常。
8. 模拟来源更新，看到动态成员和动态组变化；定义未变化时不要求重新导出。
9. 导出方案文件再导入，恢复编辑状态；工作区布局是否恢复可以作为次级能力。

## 11. 关键状态与响应式要求

至少设计并演示：

- 新建空方案与添加首个来源。
- 来源读取中、失败、重试、保留旧快照。
- 条件零匹配、精确选择部分失配、无效正则。
- 空策略组、重复组名、循环引用、删除被引用对象。
- 当前配置预览可用、因问题阻断、上次预览已过期。
- 本地保存中/已保存、导出前后、模拟超长链接。
- 不支持本地目录访问的环境。

桌面优先，建议以 1440px 左右宽度设计完整工作台，同时保证 1280px 仍能编辑。窄屏可改为分步面板或抽屉，不应仅把三列压缩到不可读。

移动端至少完成来源浏览、组与规则查看、导入和复制导出入口；复杂嵌套编辑可以使用独立全屏编辑页。本地目录能力不可用时，就近解释，不阻塞其它操作。

表格与条件控件需要清晰焦点、足够对比度、键盘操作方式；排序不能只依赖拖拽，错误不能只依赖红色。

## 12. 视觉方向

希望延续现有产品的克制深色工具感，中文为主要界面语言。品牌保持 Convertor，URL、配置与技术名称可用英文或等宽字体。

现有样式参考值：

| 用途 | 参考 |
| --- | --- |
| 页面背景 | `#0b0c10` |
| 面板 | `#12141a` |
| 次级面板 | `#1d2230` |
| 主文本 | `#e8eaf0` |
| 次级文本 | `#9aa1b4` |
| 强调色 | `#7c8cf8` |
| 成功/变化增加 | `#4ade80` |
| 提示 | `#f5b94b` |
| 等宽字体方向 | Geist Mono / JetBrains Mono |

这些是延续气质的参考，不要求机械复用每个 token。优先清晰的信息层级、紧凑但易读的密度、稳定的表格与编辑区域。

避免营销式首页、巨幅标题、装饰性仪表盘、无意义渐变光晕和每项数据一个大卡片。也不要用一屏裸 JSON 来替代交互设计。

关系可用树形、缩进、来源标识、成员块和摘要表达。若增加关系图，应作为理解依赖的辅助视图，核心任务不能依赖复杂画布操作。

## 13. 原型优先级与验收

### P0：必须完整

- 多源浏览，节点/原始组/原始规则可切换。
- 来源内批量标签与标注规则编辑。
- 固定组成员条件编辑、精确选择、多源组合、组嵌套。
- 条件摘要与实际匹配结果同时可见。
- 自定义规则与来源规则块排序、目标映射。
- 结构预览、配置预览、演示导出与重新导出状态。
- 来源预览 更新后的真实模拟重算。
- 本地草稿与方案文件恢复。

### P1：至少提供一个完整演示

- 原始组展开与保留结构的差异。
- 地区动态生成组及父组引用。
- 空组和删除被引用对象的恢复流程。
- 导出后的本地注入预览入口和不支持状态。

### 不纳入本轮

- 用户账号、云端项目、团队协作、后台持续任务。
- 官网爬取、实际网络测速、家宽真实性验证。
- 完整 Rust DSL 编辑器或正式 URL 编码实现。
- 无明确需求的通用工作流、插件市场或脚本系统。

验收重点：用户能否解释“现在有哪些成员”和“未来为什么会自动变化”，能否只维护来源标注就让使用标签的组更新，能否明确知道复制给 Surge 的是什么版本的方案。

## 15. 公共 Profile 对接约束

来源预览读取公共 Profile 的 proxies、proxy_groups、rules、proxy_providers、rule_providers。条目列表可能包含未展开的 include 与注释，不能将未加载来源显示成“已加载且为空”。Mihomo 的 use 和组内普通成员分开展示；Surge 的 policy-path 展示在所属组下，不合成根级 Provider。规则集声明与 RULE-SET 引用分开显示。

Evaluator 返回公共 Profile；完整导出使用所选基础来源的 ClientProfile 装配 General/DNS 等设置。分组仍按 group_by 从外到内逐层分桶，基础组树与后续自定义组编排保持区分。字段与验收机制见 [公共 Profile 文档](profile.md)。本轮不新增前端接口和 Angular 实现。
